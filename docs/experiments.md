## Before 3. 사진 인식 (`scripts/test_vision.py`) — 2026-09-25

**사진:** `samples/ramen.jpg`, 현재 `samples/aburasoba_1.jpg` (4000x3000 → 1024x768로 축소해서 전송). 국물 없는 마제소바/아부라소바 계열. 토핑: 적양파, 차슈(슬라이스+깍둑썰기), 멘마, 김, 튀긴 양파, 시라가네기, 고춧가루.

**모델 답변:**
> 1. 이에케
> 2. 양파, 돼지고기, 노란색 토핑, 나물, 김
> 3. 국물 색이 흰색이고 면이 굵기 때문에 이에케라멘이라고 판단됩니다.

**소요 시간:** 7.1초

**채점:**
- 종류 ❌ — 이에케 아님 (국물·시금치 없음)
- 근거 ❌ — **존재하지 않는 "흰 국물"을 봤다고 함** (할루시네이션)
- 토핑 △ — 양파·돼지고기·김은 맞음. 멘마·튀긴 양파 등은 뭉뚱그리거나 놓침

**교훈:** VLM은 "보이는 물체"는 어느 정도 잡지만, 그걸 라멘 종류로 연결하는 "판단"(도메인 지식)이 약하다. Before 2에서는 이에케를 "가는 면"이라더니 여기서는 "굵은 면이라 이에케"라고 해서 지식 자체도 일관성이 없다.
→ 설계 방향: **VLM은 시각 특징 추출만, 종류 판단은 RAG(라멘 지식 문서)로 분리.**

## Before 4. 기준 정확도 (baseline) — 2026-09-25

`scripts/eval_baseline.py`: 사진 23장, 9종류. 정답은 파일 이름(`shio_1.jpg` → shio). 모델에게는 **종류 이름 목록만** 주고(특징 설명 없음), Structured Output(JSON 스키마, label은 enum)으로 답하게 함. `temperature=0`.

| 종류 | 사진 수 | A. label 먼저 | B. 근거 먼저 (`--reason-first`) |
|---|---|---|---|
| shio | 7 | 1 | 0 |
| shoyu | 4 | **3** | 0 |
| aburasoba | 3 | 0 | 0 |
| ieke / shoyupaitan / toripaitan | 각 2 | 0 | 0 |
| donkotsu / miso / karai | 각 1 | 0 | miso 1 |
| **전체** | **23** | **4/23 = 17%** | **1/23 = 4%** (16장이 JSON 깨짐) |
| 평균 시간 | | 3.2초 | 9.1초 |

비교 기준: 9종류 무작위 찍기 ≈ 11%, "전부 shio"라고 답하기 = 7/23 ≈ 30%. **→ 7B VLM 단독은 찍기 수준.**

결과 파일: `results/baseline_label_first_*.json`, `results/baseline_reason_first_*.json`

### 관찰
1. **한 답으로 쏠림:** A에서 23장 중 12장을 `ieke`로 답함. 모르면 특정 라벨로 도망가는 편향.
2. **라벨과 근거가 모순됨:** A는 스키마상 label을 먼저 생성하고 reason을 나중에 씀 → 결론을 먼저 정하고 근거를 짜맞춤. 예: label=`ieke`인데 reason은 "돈코츠 라멘의 특징"이라고 씀.
3. **"근거 먼저"(B)는 오히려 망가짐:** 이론상 관찰→근거→결론 순서가 더 나아야 하지만, 7B 모델은 한국어 reason을 끝없이 늘어놓거나 토핑을 반복("파인애플, 파인애플, ..." / "파스타, 파스타, ...")하다 출력 상한(512토큰)에 걸려 JSON이 잘림. 모델이 작고 한국어에 약한 탓.
4. **시각 특징 추출도 불안정:**
   - 면 굵기: 23장 **전부 "가는 면"** → 쓸모없는 특징 (이에케·아부라소바는 굵은 면)
   - 국물 유무: 아부라소바 3장 중 1장만 "국물 없음"으로 맞힘
   - 국물 색: 쇼유 4/4 "진한 갈색", 토리파이탄 2/2 "뽀얀 흰색"은 그럴듯함. 시오는 투명/갈색/흰색으로 제각각
   - 토핑: 육회, 오징어, 파스타, 파인애플 등 **없는 재료를 지어냄**

### 다음 개선 아이디어
- VLM에게는 **짧은 선택형 특징만** 묻기(국물 유무, 국물 색 5지선다, 면 굵기 3지선다) → 한국어 자유 서술 줄이기
- 내부 추론은 영어로, 사용자 답변만 한국어로
- 판단은 RAG(종류별 특징 문서)로 넘기기
- 더 큰/새로운 VLM 비교 (8GB VRAM 안에서)

## 실험 5. VLM에게 "보기"만 시키기 (특징 추출) — 2026-09-25

`scripts/eval_features.py`: 라멘 종류는 묻지 않고 눈에 보이는 특징 4개만 **영어 선택형(enum)** 으로 질문. 자유 서술 없음. 각 선택지는 "어떻게 보이는지"만 정의(라멘 지식은 안 줌). 정답은 사진을 보고 직접 붙인 `data/labels.csv`.

| 특징 | 정확도 | Before 4(자유 서술)와 비교 |
|---|---|---|
| soup (국물 유무) | **23/23 = 100%** | 아부라소바 1/3 → 3/3 |
| clarity (투명/탁함) | 17/23 = 74% | — |
| color (국물 색) | 18/23 = 78% | — |
| noodle (면 굵기) | 7/15 = 47% | 전부 "가는 면" → 여전히 불안정 |
| 평균 시간 | **1.2초** | 3.2초 (출력이 짧아서) |

결과 파일: `results/features_*.json`

### 관찰
1. **질문 방식만 바꿔도 크게 좋아짐:** 같은 7B 모델인데 "종류 맞히기 + 한국어 서술" → "보이는 것만 영어 선택형"으로 바꾸자 국물 유무 100%. 반복 루프·JSON 깨짐 0건.
2. **틀리는 패턴이 일정함 (고칠 수 있는 오류):**
   - 쇼유 4장 전부 clarity=cloudy → **진하게 어두운 국물을 "탁하다"로 착각.** 색(dark_brown)은 4/4 정답이라, 쇼유 판별에는 색만으로 충분.
   - karai(붉은 국물)를 light_brown으로 봄. toripaitan_2를 pale_gold로 봄.
3. **면 굵기는 믿을 수 없음 (47%):** 1024px 축소 사진에선 면 굵기 구분이 어려움. 판단 근거로 쓰지 않거나 가중치를 낮춰야 함.
4. **라벨 확인 필요:** shio_2(약간 탁한 노란 국물), shio_4(호박색 국물), shoyupaitan_2(금색에 가까움)는 정답 라벨 자체가 애매.

### 다음 단계에 주는 의미
- 특징만으로도 종류가 상당 부분 갈림: 국물 없음 → 아부라소바 / 투명+옅은 금색 → 시오 / 진한 갈색 → 쇼유 / 뽀얀 흰색 → 토리파이탄 / 붉은색 → 카라이.
- 연갈색+탁함 그룹(돈코츠·이에케·미소·쇼유파이탄)은 **색만으로 구분 불가** → 토핑(이에케=시금치+김 3장, 미소=옥수수 등)과 RAG 지식이 필요한 지점.

## 트러블슈팅 기록

### Structured Output JSON이 중간에 잘림 (2026-09-25)
```
json.decoder.JSONDecodeError: Unterminated string ...
```
- 원인: 모델이 같은 말을 반복하는 루프에 빠져 출력이 끝나지 않음.
- 해결: `num_predict: 512`(출력 토큰 상한), `toppings`에 `maxItems: 10`, JSON 파싱 실패 시 `invalid`로 기록하고 다음 사진으로 진행.

### 이미지가 컨텍스트 한도를 초과 (2026-09-25)
```
request (4129 tokens) exceeds the available context size (4096 tokens)
```
- 원인: 4000x3000 원본 사진을 그대로 보냄. Qwen2.5-VL은 약 28x28px당 1토큰이라 큰 사진은 토큰이 많고, Ollama 기본 컨텍스트는 4096.
- 해결: Pillow로 긴 변 1024px로 축소(약 1000토큰) + `options={"num_ctx": 8192}`.
